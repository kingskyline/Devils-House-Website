Alpha v0.010 23/06/2026 - 19:12PM

Core Architecture & UI Overhaul

King Skyline [DHC]

🛠️ Overview

Over the past series of updates, the game has undergone a complete structural refactor.

The absolute goal of this update was to eliminate "spaghetti code," destroy race conditions during scene loading, drastically improve frame performance, and create a professional, decoupled UI system capable of scaling to hundreds of in-game entities.

⚙️ Technical Blueprint (Phases 1-4)

Focus: Engine Decoupling & Stability

🛡️ Phase 1: Boot System & Safe Load Order

❌ The Problem:

Managers were initializing randomly based on Unity's unpredictable execution order, causing null reference exceptions and data wipes when the save system tried to load before the grid was ready.

🔧 The Solution:

  • Implemented a strict SceneBootManager that acts as a conductor, forcing a linear Coroutine boot sequence.
  • Applied "Singleton Armor" to all managers, aggressively destroying any accidental duplicate instances.

✔ Result: The game now boots flawlessly every time. The Data layer loads first, Simulation defaults load second, the Save system injects state third, and the UI wakes up last.

🗄️ Phase 2: Central Game Database & Data Layer

❌ The Problem:

Scripts across the game (UI, Economy, Research, Build Menus) were independently querying the hard drive (Resources.LoadAll) to find assets, causing massive redundancy and hard-coupling visual data to simulation logic.

🔧 The Solution:

  • Created GameDatabaseManager, the single source of truth for all ScriptableObjects.
  • It wakes up first, caches all Maps, Buildings, Trucks, Techs, and Resources into memory lists, and serves them to the rest of the game.

✔ Result: Eliminated all scattered hard-drive loading. Menus and simulation managers now instantly pull references directly from the centralized RAM cache.

📡 Phase 3: Event System & Update Polling Removal

❌ The Problem:

UI scripts like UI_MenuController were running Update() loops up to 144 times a second, constantly querying the EconomyManager and TimeManager for data changes, wasting massive amounts of CPU overhead.

🔧 The Solution:

  • Built an ultra-lightweight GameEventBus containing static Action channels (e.g., OnMoneyChanged, OnTimeChanged).
  • Stripped all UI-pushing logic out of the simulation managers. They now simply "shout" into the Event Bus when a value changes.

✔ Result: The UI goes completely dormant to save CPU cycles, waking up for exactly 1 frame to redraw text only when a specific event fires.

🎮 Phase 4: UI State Machine & Input Routing

❌ The Problem:

Multiple UI panels had rogue, isolated Update() loops listening for the Escape key and fighting over SetActive states, leading to overlapping menus, "double-click" bugs, and the game pausing unintentionally while holding a building.

🔧 The Solution:

  • Constructed UIStateManager, a central brain governing an absolute UIState enum (None, Pause, Build, Stats, Settings, Research).
  • Enforced a strict hierarchy for the Escape key: It drops equipped tools first, closes active popup inspectors second, backs out of full-screen menus third, and pauses the game last.

✔ Result: Zero overlapping menus. Smooth, predictable transitions, and a totally bulletproof player input flow.
