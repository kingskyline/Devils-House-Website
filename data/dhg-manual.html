Quickstart & User Manual

Welcome to the DHG Monetisation & DLC Framework! This manual is designed to help you integrate downloadable content (DLC), entitlement management, and optional online services into your Unity games with minimal coding required.

Recommended Unity Version: Unity 6 or later.

1. Installing DHG

  1. Open your Unity project.
  2. Make sure the Addressables package is installed via Window > Package Manager.
  3. Import the DHG_Framework folder into your project, or install DHG through the Unity Package Manager.
  4. Initialize the Addressables system via Window > Asset Management > Addressables > Groups.

2. Creating DLC

In DHG, DLC is essentially a collection of game content that can be distributed separately from the base game. It can contain 3D models, prefabs, audio, textures, materials, scenes, and ScriptableObjects.

A recommended folder structure would be:

Assets/
└── MyGame_DLC/
    └── SwordsPack/
        ├── Prefabs/
        ├── Audio/
        ├── Textures/
        └── SwordsPackData.asset

Keeping each DLC in its own folder makes your project easier to manage as the amount of downloadable content grows.

3. Creating a DLC Profile

A DLC Profile, also called DLCData, contains the information DHG needs to identify and manage a DLC package. To create one, right-click inside the Unity Project window and select Create > DHG Framework > DLC Data.

DLC ID

Every DLC must have a unique ID (e.g., com.mygame.swordspack). This ID should remain consistent across your game, configuration files, and storefront integration.

Important: The DHG DLC ID is your framework's internal identifier. It should be mapped to the appropriate product/DLC identifier used by your chosen storefront rather than assuming every storefront uses the same ID format.

4. Adding DLC Assets

DHG uses Unity Addressables to manage downloadable content. Instead of manually writing asset-loading systems, your DLC assets can be registered as Addressables.

  1. Select the DLC asset in the Project window.
  2. In the Inspector, enable the Addressable option.
  3. Assign an appropriate Addressable address/group if required.

Once configured, the asset can be included in your Addressables build.

5. Setting DLC Dependencies

Some DLC may require other DLC to function correctly (e.g., a "Magic Swords Pack" requiring the "Base Magic Pack").

To configure a dependency, open the relevant DLCData asset, locate the Dependencies section, and add the required DLC ID. The DHG Framework will check dependencies before allowing dependent content to load.

6. DLC Versioning

DHG supports standard Semantic Versioning (MAJOR.MINOR.PATCH). Whenever you release an updated version of a DLC, update its version number in the DLCData profile.

Important: Version checking should be treated as compatibility/version validation rather than DRM.

7. Building DLC

Once configured, open Window > Asset Management > Addressables > Groups and run the Default Build Script. Unity will process your assets and generate the required content bundles.

8. Loading DLC

DHG provides a simplified API for loading DLC content.

using UnityEngine;
using DevilsHouseCreations.DHG.Core;

public class MyGameLoader : MonoBehaviour
{
    public void LoadMyDLC()
    {
        DHGManager.Instance.dlcManager.LoadDLCContentAsync(
            "com.mygame.swordspack",
            OnDLCLoaded
        );
    }

    private void OnDLCLoaded(GameObject spawnedContent)
    {
        Debug.Log("DLC successfully spawned in the world!");
    }
}

9. DLC Ownership

DHG provides an entitlement system for checking whether the player owns a DLC. This is useful for shop interfaces, unlock buttons, and save validation.

if (DHGManager.Instance.entitlementManager.IsOwned("com.mygame.swordspack"))
{
    Debug.Log("The player owns this DLC!");
}

The actual ownership verification is handled by the currently active Provider.

10. Providers

A Provider is the storefront or service responsible for telling DHG whether a player owns a DLC. Examples include Steam, itch.io, Epic Games Store, or a custom backend.

The Provider system is intentionally separated from the core DHG Framework, meaning your game does not need to be permanently tied to one storefront.

11. Development Mode

When testing inside the Unity Editor, use the Development Provider. It simulates situations like offline mode, provider failures, and missing DLC without requiring real storefront purchases.

Warning: Development Mode should only be used for testing and never enabled in a production build.

12. Steam Integration

Connect DHG to your preferred Steam SDK (e.g., Steamworks.NET or Facepunch). Configure the Steam Provider to map your internal DHG DLC IDs to the appropriate Steam product identifiers.

13. itch.io Integration

For itch.io distribution, DHG can authenticate via environment variables or desktop launcher tokens. Do not hard-code private API keys directly into your Unity project.

14. Custom Providers

If you want to support another platform (Epic, GOG, Google Play, private server), duplicate the included template DHG_CustomProviderTemplate.cs and implement the platform-specific logic.

15. Troubleshooting

If DLC fails to load, check the Unity Console. Common errors include DLC Not Owned, Dependency Missing, or Version Incompatible.

Save Game Errors

If a save requires DLC that is no longer installed, use DHGSaveValidator.ValidateSaveData() before loading the world to detect incompatible content safely.

16. Security Limitations

DHG provides a clean and reliable DLC system, but no client-side Unity framework can provide perfect DRM. The local ownership cache should not be treated as an impenetrable DRM system. For online games, never rely exclusively on the client to verify purchases. Your server should verify entitlements independently.

17. DHG Online Services (Optional)

While DHG Core is completely offline-first, you can optionally attach the DHGOnlineManager to bridge to services like Azure PlayFab, UGS, or a custom Node.js server.

  • Silent Login: Authenticate devices automatically.
  • Account Linking: Link email/passwords or storefront identities to cloud profiles.
  • Authoritative Sync: Securely cache authoritative cloud entitlements locally.

18. Online API Reference

// Silent Device Login
DHGManager.Instance.onlineManager.LoginSilently((success, message) => { ... });

// Account Linking
DHGManager.Instance.onlineManager.LinkEmailAccount("player@email.com", "Password!", (s,m) => { ... });

// Cloud Sync
DHGManager.Instance.onlineManager.SynchronizeEntitlements((success, message) => { ... });

19. API Reference

  • DHGManager.Instance - The main framework singleton.
  • DHGManager.Instance.dlcManager.LoadDLCContentAsync(...) - Loads content securely.
  • DHGManager.Instance.entitlementManager.IsOwned(...) - Validates ownership status.
  • DHGErrorHandler.GetPlayerFacingMessage(state) - Converts technical errors into localized player messages.

20. Recommended DHG Architecture

A typical setup separates the core game, DLC content, and provider logic. The framework acts as the intermediary:

Game
  ↓
DHG Framework
  ├── DLC System
  ├── Entitlement System
  ├── Provider System (Steam/Itch)
  └── Optional Online System
          ↓
     Cloud Backend

21. Best Practices

  • Use Stable IDs: Never change a DLC ID after public release.
  • Keep DLC Modular: Separate DLC content physically from base-game folders.
  • Treat Servers as Authoritative: For competitive or online economies, trust the server, not the client.

22. Final Notes

The core philosophy is: Build once. Reuse across games. Keep the storefront replaceable. Keep the backend replaceable. Your game should depend on DHG's internal systems rather than being tightly coupled to a single storefront SDK.
